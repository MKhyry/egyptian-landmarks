# 🏛️ AI-Powered Egyptian Landmark Recognition System

> **A Vision Transformer application for recognizing Egyptian archaeological landmarks from photographs.**  
> Built with CLIP (ViT-B/32), cosine similarity matching, and Explainable AI attention visualization.

This is a college AI course project. The focus is on **transformer-based image understanding**, not web development. The backend, frontend, and Colab prototype all exist to demonstrate one idea: how a Vision Transformer turns a photograph into a semantic fingerprint, and how that fingerprint can identify an ancient landmark.

---

## What the System Does

A user uploads a photograph of an Egyptian landmark. The system:

1. Passes the image through CLIP's Vision Transformer — splits it into 49 patch tokens, runs 12 layers of self-attention
2. Produces a 512-dimensional embedding vector — a semantic fingerprint of the image
3. Compares that vector against precomputed reference embeddings using cosine similarity
4. Returns the landmark name and confidence score if the similarity exceeds the threshold
5. Generates an Explainable AI heatmap showing which image regions the transformer focused on

If no match exceeds the threshold, the system returns: **"Landmark not recognized"**.

## AI Stack

| Component | Technology | Purpose |
|-----------|------------|---------|
| Vision Transformer | CLIP ViT-B/32 (OpenAI) | Image feature extraction |
| Embedding | 512-dimensional L2-normalized vector | Semantic image fingerprint |
| Matching | Cosine similarity | Nearest-neighbor search |
| Explainability | Attention rollout (Abnar & Zuidema, 2020) | XAI heatmap |
| Framework | PyTorch + open-clip-torch | Model loading and inference |

**Why CLIP and not a custom-trained model?**  
CLIP was pretrained on 400 million image-text pairs. Its Vision Transformer already understands the visual concepts relevant to Egyptian landmarks without any fine-tuning. New landmarks can be added by indexing images — no retraining required.

## Setup

### 1. Clone the repository

```bash
git clone https://github.com/your-username/egyptian-landmarks.git
cd egyptian-landmarks
```

### 2. Add your dataset

Place landmark images in `backend/dataset/`. Each landmark gets its own subfolder. The folder name becomes the `landmark_id` used throughout the system.

```
backend/dataset/
  pyramids_of_giza/
    img001.jpg
    img002.jpg
  great_sphinx/
    photo1.jpg
  karnak_temple/
    ...
```

Also place gallery images (shown on the result page) in `backend/gallery/` using the same folder structure.

### 3. Backend

```bash
cd backend

# Create and activate virtual environment
python -m venv venv
source venv/bin/activate        # macOS / Linux
# venv\Scripts\activate         # Windows

# Install dependencies
pip install -r requirements.txt

# Configure environment
cp .env.example .env
# Edit .env if needed (MongoDB URL, model name, threshold)

# Add your landmark data
# Open data/landmarks_data.py and fill in the LANDMARKS list

# Index your dataset — run once, takes 1–3 minutes on CPU
python scripts/build_embeddings.py

# Seed MongoDB with landmark info
python scripts/seed_landmarks.py

# Start the server
uvicorn main:app --reload
```

API is now running at `http://localhost:8000`.  
Interactive docs at `http://localhost:8000/docs`.

### 4. Frontend

```bash
cd frontend
npm install
npm run dev
```

App is now running at `http://localhost:3000`.

## Environment Variables

Copy `backend/.env.example` to `backend/.env`:

```env
MONGODB_URL=mongodb://localhost:27017
DATABASE_NAME=egyptian_landmarks

CLIP_MODEL_NAME=ViT-B-32
CLIP_PRETRAINED=openai

# Recognition threshold: 0.0–1.0
# Below this cosine similarity score → "Landmark not recognized"
SIMILARITY_THRESHOLD=0.65

DATASET_PATH=./dataset
EMBEDDINGS_PATH=./embeddings_store

MAX_UPLOAD_SIZE_MB=10
ALLOWED_ORIGINS=http://localhost:3000
```

## Adding a New Landmark

No retraining needed. Three steps:

1. **Add images** — create `backend/dataset/your_landmark_name/` and add photos
2. **Add info** — add an entry to `backend/data/landmarks_data.py`
3. **Re-index** — run `python scripts/build_embeddings.py` and `python scripts/seed_landmarks.py`

## Tuning Recognition Accuracy

The `SIMILARITY_THRESHOLD` in `.env` controls how strict the matching is:

| Value | Effect |
|-------|--------|
| 0.50 | Lenient — more matches, higher risk of false positives |
| 0.65 | Balanced — good default starting point |
| 0.80 | Strict — only high-confidence matches accepted |

After uploading test images, the result page shows all similarity scores in the **AI Reasoning** panel, which helps determine the right threshold for your dataset.
